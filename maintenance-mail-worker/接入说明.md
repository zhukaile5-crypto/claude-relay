# M11 邮件通知：待 Claude 验收和部署

本轮仅在独立开发分支新增模块、Worker 和模拟测试。未修改 Cloudflare 账户、域名、正式配置或服务，未部署，也未发送任何真实邮件。单测成功不能证明收件箱或手机已经收到邮件。

## 通知范围与本机接入

默认只发送以下三类事件：进入受限模式（`isolation-blocked`）、升级失败（`upgrade-failed`）、自动退回（`rolled-back`）。网页原有机主横幅继续保留；邮件配置缺失、禁用、发送失败时不能阻止维护任务或替代横幅。

维护入口通过 `tools/maintenance-mail-config.cjs` 读取本副本的 `data/maintenance/mail-config.json`，再调用 `tools/maintenance-notify.cjs`；不会读取平台登录密钥作为通知凭据。配置参考 `tools/maintenance-mail.example.json`，缺失或 `enabled: false` 时不发送。入口把通知状态目录固定为本副本的 `data/maintenance/mail/`，覆盖样例的 `stateDir`，避免测试副本写正式状态。每轮最多重试 5 项，预算不足十秒时停止；升级中断恢复优先于邮件重试；恢复和候选清理后、运行故障处理前重试，避免受限状态的提前返回一直饿死待发通知。

```js
const { notify, retryPending } = require('./maintenance-notify.cjs');
const options = { config: maintenanceMailConfig };

// 每次维护入口调用，以便处理以前失败的邮件；关闭时直接返回 disabled。
await retryPending(options);
const result = await notify({
  type: 'upgrade-failed',
  program: 'claude',
  version: '2.1.999',
  reason: 'acceptance-failed',
  // 可选：对同一组故障状态计算 SHA256；禁止传原始日志或路径。
  issueFingerprint: 'a'.repeat(64),
}, options);
// result 只有固定状态码及非机密的事件摘要 id，可由调用方安全记录。
```

- `program` 仅允许 `claude/codex/relay/runtime`；`version` 仅允许有限长度版本号或 `unknown`。
- `reason` 仅允许 `fingerprint-mismatch/acceptance-failed/download-failed/version-unreadable/restart-failed/runtime-failure/interrupted/unknown`。不知道原因时用 `unknown`，不要塞入异常消息。
- 没有提供 `issueFingerprint` 时，由类型、程序、版本、原因生成摘要。该默认值会把同版本同原因的再次出现视为同一问题；如需区分新的故障状态，调用方应提供稳定的状态摘要。不可每次用时间生成新摘要。
- 发送内容仅包含三类事件及程序、版本、通用原因、UTC 时间。摘要只用于去重，不写入邮件。原始对话、错误输出、文件内容、路径、密码、令牌不会序列化。
- 独立共享密钥通过 `secretEnv` 指定的环境变量读取，不写入通知配置、状态、日志或仓库；不能复用平台登录密码、叫醒令牌、GPT API key 或 Claude 凭证。
- `notify` 返回 `disabled/config-error/ignored/sent/duplicate/deferred/pending/state-error`。未发送的故障保留原横幅。不要把 `pending` 说成邮件已送达。
- 状态按事件摘要分别原子写入 `stateDir`。成功才记为已发；失败保留待发，默认十五分钟后可重试。运行任务应周期调用 `retryPending`；模块自身不创建定时器或计划任务。每次最多处理一百个待发记录。
- 状态目录不可让模型任务写入。删除去重状态可能使旧问题再次提醒。发送前无法写状态时会停止发送。多进程间的最终去重由云端的同一个持久化对象负责，本机串行队列只协调当前进程。

## Worker 约束

`maintenance-mail-worker/` 是独立 Worker，不修改既有叫醒 Worker 或它的路由。

只接受 `POST /notify`、JSON、独立 Bearer 密钥；正文最多 2048 字节。固定字段、类型、版本、原因和时间全部校验，拒绝额外的收件人、邮件正文、附件、原始日志字段。没有 CORS 开放设置，网页或模型不应持有此密钥。

发送使用 Cloudflare 当前官方结构化 `env.EMAIL.send({to,from,subject,text})` 接口。收件人来自 Worker 配置，并由 `send_email.destination_address` 再限制为同一个已验证邮箱；请求体无法改变收件人、发件人或模板。接口响应不会返回原始服务商异常。

一个机主对应一个 SQLite Durable Object，所有请求串行处理。已发送的事件持久去重；发送失败五分钟后可重试，不同事件也至少间隔一分钟。本机默认重试周期为十五分钟。去重记录最多 512 条，达到容量后拒绝新发送并返回 `ledger-full`，不能静默丢弃旧记录后重复发送；由 Claude 审查后再安排归档或扩容。

仍有分布式系统限制：邮件服务接受请求后、成功记录落盘前发生崩溃，重试可能造成重复邮件；当前官方发送接口没有在此实现可用的幂等键。因此不宣称严格“恰好一次投递”。收件箱垃圾邮件策略、退信、网络故障也可能影响送达。本机断电或完全断网时，本机事件不能及时送出；本次没有实现云端掉线监测。

## 费用与账户前提

截至 2026-11-01 的官方文档，向 Cloudflare 账户内已验证收件地址发送邮件，在 Free/Paid 计划均免发送费。Worker 请求和 Durable Object 计算、存储仍受套餐额度/费用约束，不能据此保证整项服务绝对零费用。示例采用 SQLite Durable Object，Free 计划支持；超出免费额度的操作会失败。若改为任意收件人，须另外核对付费计划和费用，本方案不开放任意收件人。

账户需具备可用 Worker、已接入的发件域名、已验证的机主收件邮箱和邮件发送绑定。当前账户是否满足这些条件未检查，也未操作 DNS、MX、域名或邮箱。任何邮件域名设置均应由 Claude 与机主核对现有邮箱用途后执行。
